=== Sensitive Data Masking

DPM automatically masks sensitive data in debug output to prevent accidental exposure.

==== Masked Keywords

These variable names trigger automatic masking:

[cols="1,3", options="header"]
|===
| Keyword | Examples

| password, passwd, pwd
| `password`, `db_passwd`, `user_pwd`

| token, secret
| `api_token`, `jwt_secret`, `auth_token`

| api_key, apikey, access_key
| `api_key`, `apikey`, `AWS_ACCESS_KEY`

| private_key, ssh_key
| `private_key`, `ssh_key`, `ssl_private_key`

| auth, authorization, bearer, jwt, session
| `auth_token`, `authorization`, `bearer_token`
|===

==== Example

[source,lisp]
----
;; These are automatically masked in debug output
(rust-env-set "DATABASE_PASSWORD" "secret123")
(rust-env-set "API_KEY" "abc123xyz")
(rust-env-set "JWT_TOKEN" "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9")

(debug)  ;; Shows: DATABASE_PASSWORD = ******, API_KEY = ******, JWT_TOKEN = ******
----

IMPORTANT: Even with automatic masking, avoid logging sensitive data in production environments.
