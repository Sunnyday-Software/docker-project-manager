= Command System
:navtitle: Command System
:description: DPM's extensible command architecture

== Overview

DPM's command system is designed for extensibility through a trait-based architecture. Commands can be implemented as structs or closures.

[plantuml, command-system, svg]
----
@startuml
!theme cerulean

interface Command {
  +execute(args: Vec<Value>, ctx: &mut Context) -> Result<Value, String>
  +name() -> &'static str
  +description() -> &'static str
  +syntax() -> &'static str
  +examples() -> &'static str
}

class CommandRegistry {
  -commands: HashMap<String, Box<dyn Command>>
  +register(cmd: impl Command)
  +get(name: &str) -> Option<&dyn Command>
  +execute(name: &str, args: Vec<Value>, ctx: &mut Context) -> Result<Value, String>
}

class ClosureCommand {
  -name: String
  -description: String
  -syntax: String
  -examples: String
  -function: Box<dyn Fn(Vec<Value>, &mut Context) -> Result<Value, String>>
}

Command <|.. ClosureCommand
CommandRegistry o-- "many" Command

@enduml
----

== Command Trait

=== Trait Definition

[source,rust]
----
pub trait Command {
    fn execute(&self, args: Vec<Value>, ctx: &mut Context) -> Result<Value, String>;
    fn name(&self) -> &'static str;
    fn description(&self) -> &'static str;
    fn syntax(&self) -> &'static str;
    fn examples(&self) -> &'static str;
}
----

=== Required Methods

[cols="1,3", frame=none]
|===
| *Method* | *Description*

| `execute` | Command implementation
| `name` | Command name (for lookup)
| `description` | What the command does
| `syntax` | How to call the command
| `examples` | Usage examples
|===

=== Example Implementation

[source,rust]
----
pub struct PrintCommand;

impl Command for PrintCommand {
    fn execute(&self, args: Vec<Value>, ctx: &mut Context) -> Result<Value, String> {
        let mut result = String::new();
        for arg in args {
            match arg {
                Value::Str(s) => result.push_str(&s),
                Value::Int(i) => result.push_str(&i.to_string()),
                _ => return Err("Invalid argument type".to_string()),
            }
        }
        Ok(Value::Str(result))
    }

    fn name(&self) -> &'static str { "print" }
    fn description(&self) -> &'static str { "Concatenate and print values" }
    fn syntax(&self) -> &'static str { "(print arg1 arg2 ...)" }
    fn examples(&self) -> &'static str { "(print \"Hello\" \"World\")" }
}
----

== Closure Commands

=== Registration

Commands can be registered as closures:

[source,rust]
----
registry.register_closure(
    "my-cmd",
    |args, ctx| {
        Ok(Value::Str("result".to_string()))
    }
);
----

=== With Metadata

Closures can include metadata:

[source,rust]
----
registry.register_closure_with_help(
    "my-cmd",
    "Does something useful",
    "(my-cmd arg1 arg2)",
    "(my-cmd \"hello\" 42)",
    |args, ctx| {
        Ok(Value::Str("result".to_string()))
    }
);
----

== Command Execution

=== Execution Flow

1. Parse S-expression
2. Look up command in registry
3. Evaluate arguments
4. Execute command
5. Return result

=== Example Execution

[source,lisp]
----
(+ 1 2 3)
----

Execution:

[source]
----
1. Parse: List[Symbol("+"), Int(1), Int(2), Int(3)]
2. Lookup: Find "+" in registry → SumCommand
3. Evaluate args: [1, 2, 3]
4. Execute: SumCommand.execute([1, 2, 3])
5. Return: Int(6)
----

== Error Handling

=== Error Types

[cols="1,2", options="header"]
|===
| Error | Description

| Command not found | Unknown command name
| Type mismatch | Wrong argument type
| Argument count | Wrong number of arguments
| Runtime error | Command execution failed
|===

=== Error Propagation

Errors propagate through the call stack:

[source,lisp]
----
(+ 1 (error-command))
; => Error: Unknown command: error-command
----

== Performance

=== Optimization

1. **Command caching**: Frequently used commands cached
2. **Lazy evaluation**: Arguments evaluated on demand
3. **Minimal allocations**: Reuses values when possible

=== Benchmarks

[cols="1,1", options="header"]
|===
| Operation | Time

| Command lookup | < 1μs
| Argument evaluation | < 10μs
| Command execution | Varies by command
|===

== Security

=== Command Validation

Commands are validated before execution:

[source,rust]
----
// Commands cannot access unauthorized resources
// All file operations go through rust-fs-* commands
// All process operations go through rust-process-* commands
----

=== Sandboxing

Commands run in a sandboxed environment:

1. **No direct system access**: All operations through DPM commands
2. **Type safety**: Rust's type system prevents many errors
3. **Input validation**: Arguments validated before use
